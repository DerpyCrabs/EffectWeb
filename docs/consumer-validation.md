# Consumer validation — 0.2.3 candidate

> Historical 0.2.3 validation record. These counts and compiler restrictions describe that candidate, not 0.4.0. See the [0.4.0 migration guide](migration-0.4.0.md) for the current contracts.

Validated on 2026-09-08 against packages built from `bdfbffa`. The five real consumer projects were changed and tested directly. Their existing manifests and lockfiles were preserved; the candidate was installed into their actual `node_modules` from local tarballs with `npm install --no-save --ignore-scripts`. Nothing was published.

## Commands and boundaries

The candidate build used `npm run build`, `node scripts/stage-native.mjs`, and `npm run pack:release -- --local`. Framework validation used `npm run check`, `npm test`, `npm run test:compiler`, `npm run check:browser`, `EFFECTWEB_TEST_PORT=4328 npm run test:browser`, `npm run test:package`, and `npm run measure:bundles`.

Consumer validation used each project's actual check/build/unit/browser commands. SparkSwarm's browser harness ran on port 4338 with its temporary Store; TeleVecha on 4188; Inbox on 4320 with fixture settings; LocalChat used unused app/provider ports and disposable data. Existing user changes were preserved. Live accounts, production databases, running coordinators and published benchmark results were not used as fixtures. Task-owned servers were stopped after testing.

Because these are no-save candidate installs, a later clean dependency install will restore the versions declared by each consumer. Release/dependency pin updates remain a separate action.

Optional mobile WebKit checks could not execute: the required browser downloaded successfully, but its runtime needs unavailable system libraries (`libicu74`, `libxml2`, and `libflite1`). No OS packages were changed. These checks are not counted as passes; browser results above are Chromium.
