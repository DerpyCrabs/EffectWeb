# EffectWeb 0.11.0

EffectWeb 0.11 removes the `Snapshot` type and the exports that no application used, widens model types so `AsyncResult` fields no longer need a cast, and drops the lint rule that never fired. The changes come from reading the seven local applications built on EffectWeb and the agent sessions that wrote them: the type errors and lint diagnostics those sessions hit most are the ones removed here. This is a breaking pre-1.0 release. Upgrade `effectweb` and every `@effectweb/*` package together to `0.11.0`.

## Highlights

- Published data keeps the application's own types. `Snapshot<T>`, `SnapshotOpaque` and `snapshotOpaque` are gone; views, `update`, `receive`, `owner.read()`, rows and query results carry the declared model type. Declare `readonly` in your own model types where you want it. Development builds still freeze published objects and arrays so a mutation throws where it happens; production builds skip the pass.
- `modelOwner`, `component` `init` and `program` `initial` publish a field declared with `AsyncResult.initial<A, E>()` as `AsyncResult<A, E>`, so the `AsyncResult.initial() as …` cast is no longer needed. The new `ModelFields<State>` type names this widening for generic helpers.
- Components receive their owner through a factory, `component({ init }, owner => view(…))`, instead of `ownerOf(patch)`; `observeQuery` works inside a component because component owners now have `own` and `disposed`.
- A controller hands its cleanup over as `lifetime` only, usually `lifetime: owner`; any other `dispose` or `close` the controller returns is an ordinary action.

## Migrating from 0.10.x

- Replace `Snapshot<T>` with `T`, and remove `as unknown as` casts that converted between the two. Where a model field or prop is declared as a mutable array but receives one the framework published, declare it `readonly`.
- Remove `AsyncResult.initial() as AsyncResult<A, E>` casts; write `AsyncResult.initial<A, E>()`. A helper that is generic over a model type should declare its model as `ModelFields<M>`.
- `ownerOf(patch)` is removed. Pass `owner => view(…)` as the second argument of `component({ init })` and start work through that owner in event handlers.
- `ViewBinding` is removed. A child view that reports to a parent takes `send` as a prop, typed `Send<Message>`; only a view placed by `component`, `program` or `mount` declares a message type as its second type argument.
- `Slot<A>` is removed; type a render-callback prop as a function, `(item: Item) => JSX.Element`.
- `submit` is removed; call `event.preventDefault()` in the handler.
- `domHandle` and `DomHandle` are removed; keep the element with `domMount` or a local helper.
- The `component({ program, receive })` form is removed; use a `controllerView` whose action handles the message.
- `ModelOwner.transaction` is removed; batch several changes in one `patch`. `ModelOwner.isRunning` and the `RunningProgram` members `activeKeys`, `awaitStopped` and `isRunning` are removed.
- `Mounted` is no longer callable; use `mounted.dispose()`. The `mount` and `makeMount` overloads that took `send` in the options or a controller object are removed; `controllerView` is the one path to `model.actions`.
- A controller's teardown is `lifetime: ControllerLifetime`, an object with `dispose` and an optional `close`, so `lifetime: owner`. A `dispose` or `close` member next to the actions is no longer treated as teardown.
- `@effectweb/query`: `invalidateWhere`, `removeQuery`, `onReset` and `retryPage` are removed, and `infiniteQuery` no longer accepts `maxPages`. `resetResources` stays.
- `programDriver` was already removed in 0.10; `effectweb/testing` is otherwise unchanged.

## Compiler and lint

- EW2002 and the `effectweb/query-key` rule are gone; the preset enables four rules. A `key` field on a query is rejected by its type, whose message says what to do. Remove `"effectweb/query-key"` from any lint configuration that listed it explicitly.
- `console` is a known global in views, so a debug log is no longer an EW2001 error.
- EW1005 follows immutable local Effect bindings and same-file helper calls, including aliases for Effect imports, when it checks finalizers under `replace`.
- The render lint no longer special-cases a `submit(…)` callback.
- The compiler README no longer claims the freeze runs in every build; the query README no longer lists the removed cache methods.

## Runtime

- Freezing published data is development-only. The Vite plugin defines `__EFFECTWEB_DEV__` as `true` for `serve` and `false` for `build`; when the define is absent, for example in tests under Node, the freeze runs. Freezing cost about one microsecond per object and 7% of a 1000-row mount in the benchmark application.
- `component` infers `State` from `init` alone, so `update`, `receive` and `view` can be written without repeating the type.
- Ownership is passed through per-placement view factories instead of an owner lookup; setup reentrancy and cleanup are covered by regression tests.

## Documentation and website

- A rewritten "Why EffectWeb" explains the two purposes: Effect without an adapter layer between it and the screen, and fewer ways for code, including code written by an agent from the documentation, to be wrong.
- "Which API to use" is a decision page organised by question rather than a list of application tasks.
- The site draws its icons and brand mark as inline SVG instead of characters that fell back to system fonts, uses CSS chevrons for sidebar groups, and turns off code ligatures.
- Guides use `AsyncResult.initial<A, E>()` and the owner factory form of `component`; the compiler page documents the four-rule preset.

## Validation

Local validation passed the unit, browser, package-smoke, bundle-budget, documentation-snippet and site checks, the Rust compiler tests, and the checks, unit tests, builds and browser suites of the seven local consumer applications on the rebuilt packages.
