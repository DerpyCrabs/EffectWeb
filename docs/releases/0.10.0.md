# EffectWeb 0.10.0

EffectWeb 0.10 removes three exports that had no consumer, drops a cast from the documented `AsyncResult` idiom, makes list rows cheaper to mount, and moves the documentation site to Astro. This is a breaking pre-1.0 release. Upgrade `effectweb` and every `@effectweb/*` package together to `0.10.0`.

## Highlights

- Lists are cheaper: rows mount with fewer DOM calls and allocations, an edit that keeps the same keys updates rows in place without rebuilding key sets, and replacing every row clears the list in one operation. On the js-framework-benchmark app, script time drops by 10% for creating rows, 20% for replacing them and 30% for updating every tenth row, and run memory drops by 13%.
- The documentation no longer casts `AsyncResult.initial()`. Declare the model type on `modelOwner<Model>` or `component<Props, State>` and the field is typed `AsyncResult<A, E>`.
- The documentation site is an Astro static build with in-place navigation and link prefetching.

## Migrating from 0.9.x

- `slot(render)` is removed. Pass the render function itself; the `Slot<A>` type stays for typing a render-callback prop.
- `liveSource` is removed. Publish subscription data through a controller's `modelOwner`, or through a `projectionSource` from `effectweb/advanced`, and observe its source.
- `programDriver` is removed from `effectweb/testing`. Use `program.awaitIdle(key?)`, `program.isRunning(key)` and `program.close()` directly; `controlledEffect` and `renderView` are unchanged.
- The compiler no longer treats `slot` as a render root and EW3004 no longer names `liveSource`.

## Runtime

- Controlled inputs track edits and IME composition through the mount root's capture listeners instead of three listeners per element.
- Delegated event types dispatched without bubbling (for example a synthetic `new Event('click')`) reach their handler through a one-shot listener armed during capture; the handler runs in native target order as before. Elements under no mount root or portal host no longer receive such events, which matches how bubbling events already behaved.
- Attributes of elements cloned from a compiled call site are written directly; cloned inline styles are read when a dynamic style object first replaces them.
- A keyed list whose keys are unchanged updates rows in place; rows from `entities`, `sequence` or a `collection` are not checked for duplicate keys a second time. A list whose rows are all replaced, and that fills its container, is cleared with one `replaceChildren` call before the new rows are built.
- Each list row is one object, element bindings are a plain record, and delegated event keys are cached.
- Published arrays are frozen by index. Properties stored at array indices are read directly; an accessor at an index is evaluated, while accessors on other properties of an array or on plain objects are still left alone.

## Documentation and website

- Guides declare the model type instead of casting `AsyncResult.initial()`.
- The `clock` source is described in one sentence under Views; the DOM guide covers elements only.
- `website/` is a standalone Astro project with its own dependencies. Run `npm run install:site` once; CI and Netlify do.

## Validation

Local validation passed the unit, browser, package-smoke, bundle-budget, documentation-snippet and site checks, the Rust compiler tests, and the checks, unit tests and browser suites of the seven local consumer applications on the rebuilt packages. The js-framework-benchmark EffectWeb-only rerun is recorded in that checkout's local notes.
