# EffectWeb 0.12.0

EffectWeb 0.12 adds two component packages: `@effectweb/base-ui`, a headless port of Base UI driven by explicit handles, and `@effectweb/shadcn`, shadcn/ui on top of it, available both as a package and through the upstream shadcn CLI.

## Highlights

- `@effectweb/base-ui`: the Base UI anatomy as unstyled parts. A handle created in a controller (`createDialog()`, `createMenu()`, `createSelect()`) replaces React context: parts receive it as a prop, observe it independently, and the controller's owner owns its lifetime. Overlays use native `<dialog>` and the Popover API; placement is a viewport flip-and-shift helper without Floating UI. Families: Dialog, AlertDialog, Drawer, Popover, Tooltip, Menu, ContextMenu, Menubar, NavigationMenu, Select, Combobox, Autocomplete, Tabs, Collapsible, Accordion, Checkbox, Switch, RadioGroup, Toggle, ToggleGroup, Slider, NumberField, Toolbar, ScrollArea, Toast, Field, Fieldset, Avatar, Progress, Separator and Input.
- `@effectweb/shadcn`: the 44 base-nova families plus Combobox, HoverCard, NumberField and Toolbar, with the upstream Tailwind v4 classes and theme tokens. Simple families take props and item arrays (`Dialog title=… footer=…`, `DropdownMenu items=…`); families that upstream composes through context take a base-ui handle and export the upstream part names. Dialog, AlertDialog, Popover, Sheet and Drawer export their parts for split layouts.
- The shadcn CLI installs EffectWeb components from `https://effectweb.netlify.app/r/{name}.json`: add the `@effectweb` registry to `components.json` and run `npx shadcn add @effectweb/button @effectweb/theme`. The registry is generated from the package source by `npm run registry:build`; `npm run check` fails when it is stale, and `npm run test:registry` installs every item with the real CLI into a clean Vite project and builds it.

## Runtime

- Base UI checkbox, switch and radio handles restore their initial state after form resets inside shadow roots, including cancellation and disposal handling.
- Owner publications reuse protected snapshots, and equivalent style and class bindings avoid redundant DOM writes while preserving declaration order and external changes.

- `JSX.EventResult` includes `null` and `undefined`, so a conditional handler such as `onChange={() => enabled ? save() : null}` type-checks. These results are ignored like booleans.
- After a native form reset, controlled properties are restored from the model once the reset handlers have run: `value` of inputs, textareas, selects and form-associated custom elements, `checked`, and `selected` of options in a multiple select, including controls associated through the `form` attribute. A cancelled reset leaves the draft untouched.

## Compiler and lint

- EW3008 flags a `domBinding` setup that reads `input()` once while acquiring and returns no `update`: later data never reaches the element. Read `input()` in event handlers or `update`, or key the binding by what it attaches to with `identity`. The headless Base UI parts that had this bug now key their bindings by their handle.
- The lint preset reports a suppression that no longer suppresses anything (`reportUnusedDisableDirectives: 'error'`), in both the JSON and the JavaScript form. Remove stale `oxlint-disable` comments when upgrading.

## Build and development

- Release versioning updates internal dependencies as well as peers and native packages, keeping shadcn, Base UI and icons on the same release.

- Icon packages are generated before declarations, so generated icon modules resolve during declaration generation; `.css` files in a package are copied to `dist`.
- The workspace adds `tailwindcss` and `shadcn` as development dependencies for the browser fixtures and the registry smoke test. The runtime does not depend on either.
- The browser tests resolve workspace packages to their sources, so they never run against an outdated build.
- A unit test checks that every public export has a description before the API reference is generated; `build:js` lists every missing one at once.

## Documentation

- New guides: shadcn/ui components, the headless Base UI layer, and live data (stable rows, holding updates while reading, fixed layouts and clock-driven times). The API reference covers both packages.
